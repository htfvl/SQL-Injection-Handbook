## 🟢 04.6) ALTERNATIVE INJECTION POINTS / АЛЬТЕРНАТИВНЫЕ ТОЧКИ ВНЕДРЕНИЯ

Хотя подавляющее большинство SQL-инъекций происходит в теле оператора `SELECT` внутри конструкции `WHERE`, уязвимость может возникнуть абсолютно в любой части SQL-запроса и в совершенно разных типах инструкций СУБД.

---

### 1️⃣ Инъекции в операторе `UPDATE`
Используются приложениями при редактировании профиля пользователя, изменении настроек или корзины.
* **Внутри обновляемых значений:**
  Если бэкенд выполняет запрос вида:
  ```sql
  UPDATE users SET email = '$user_input' WHERE id = 42
Внедрение в параметр email опасных конструкций (например, через подзапросы Subqueries) может позволить обновить чужие данные или вытащить инфу через ошибки (Error-based).

Внутри конструкции WHERE:

SQL
UPDATE products SET price = 10 WHERE id = '$user_input'
⚠️ Критическая опасность: Если в параметр id прилетит пейлоад с обрывом логики (1' OR 1=1--+), оператор обновит цены вообще для всех товаров в базе данных, что приведет к нарушению целостности бизнес-логики.

2️⃣ Инъекции в операторе INSERT
Обычно встречаются на формах регистрации новых пользователей, создании отзывов, отправке тикетов в саппорт или логгировании действий.

SQL
INSERT INTO testimonials (user, comment) VALUES ('liquidgenius', '$user_input')
Если внедрить пейлоад в поле comment, можно закрыть оригинальный VALUES и через запятую дописать создание новой строки с правами администратора, либо использовать функции извлечения данных в цикле.

3️⃣ Инъекции внутри названий таблиц или столбцов (TABLE / COLUMN NAMES)
Иногда приложения динамически подставляют имя таблицы или столбца на основе выбора пользователя (например, при переключении между таблицами логов logs_2025 и logs_2026).

SQL
SELECT * FROM $table_name WHERE active = 1
⚠️ Особенность: В этой точке невозможно использовать комментарий --+ для сокрытия остатка запроса, если этот остаток синтаксически необходим для выполнения. Кроме того, имена таблиц нельзя передавать в виде строковых литералов (в кавычках), из-за чего стандартные пейлоады здесь бессильны и требуют глубокого знания структуры конкретной СУБД.

4️⃣ Инъекции внутри конструкции ORDER BY
Встречаются повсеместно на страницах каталогов, где реализована сортировка товаров по цене, дате или популярности.

SQL
SELECT id, name, price FROM products ORDER BY $sort_column
Специфика: С синтаксической точки зрения, оператор ORDER BY идет в самом конце запроса SELECT, поэтому стандартные трюки с UNION здесь часто не работают без ломания структуры.

Как эксплуатировать: Здесь отлично залетают техники Blind SQLi (Слепые инъекции). Сюда внедряют условные конструкции (например, CASE WHEN (условие) THEN price ELSE name END), заставляя базу менять порядок сортировки строк в зависимости от истинности булева выражения. Если при верном условии таблица отсортировалась по цене, а при ложном — по алфавиту, мы можем посимвольно вытаскивать любые данные.
