## 🟢 05_DATA_EXFILTRATION / ПОЛУЧЕНИЕ СКРЫТЫХ ДАННЫХ

Допустим, есть веб-приложение для покупок, которое отображает товары по категориям. Когда пользователь нажимает на категорию **Подарки**, браузер запрашивает URL: 
`https://shop.com/products?category=Gifts`

В ответ на это приложение выполняет SQL-запрос для получения соответствующих товаров из БД:
```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
🔍 SYSTEM_ANALYSIS / РАЗБОР ЗАПРОСА:
SELECT * — Выбрать все доступные столбцы (символ * в языке SQL означает ALL).

FROM products — Из таблицы products.

WHERE category = 'Gifts' AND released = 1 — Где категория равна 'Gifts' AND флаг released равен 1. (Допустим, это булев флаг, означающий, что товар активен и выпущен в продажу, а не его количество).

Приложение не реализует никакой защиты от SQLi. Это значит, что атакующий может спроектировать вектор атаки прямо через URL.

⚔️ EXPLOITATION STAGE_01 / ОБХОД ФИЛЬТРАЦИИ КАТЕГОРИИ
Отправляем в параметр модифицированную строку:
https://shop.com/products?category=Gifts'--+

Разбор пейлоада:

Gifts' — Одинарная кавычка принудительно закрывает строковое значение параметра category внутри SQL-запроса, ломая его оригинальную структуру.

--+ — Начало комментария в SQL (знак + в URL заменяет пробел, который синтаксически необходим после дефисов). Все, что идет после --+, базой данных просто игнорируется.

В итоге измененный запрос на бэкенде трансформируется в:

SQL
SELECT * FROM products WHERE category = 'Gifts'--+' AND released = 1
Условие AND released = 1 полностью отсекается и уходит в комментарий. База данных возвращает абсолютно все товары из категории, включая скрытые новинки, которые еще не были запущены в продажу.

⚔️ EXPLOITATION STAGE_02 / ВЫВОД ВСЕЙ ТАБЛИЦЫ
Также можно провести аналогичную атаку и вызвать отображение вообще всех продуктов из всех категорий сразу, включая те, о которых атакующий даже не знает:
https://shop.com/products?category=Gifts'+OR+1=1--+

Измененный запрос на бэкенде примет вид:

SQL
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--+' AND released = 1
Результат: Запрос возвращает элементы, где либо category = 'Gifts', либо 1=1. Так как логическое тождество 1=1 истинно всегда (TRUE), условие WHERE срабатывает для каждой строчки в таблице products, и база данных сливает весь свой контент на страницу.

⚠️ [CRITICAL_WARNING]
Нужно быть предельно осторожным при внедрении условий типа OR 1=1. Даже если в контексте выборки данных (SELECT) это кажется безопасным, приложения часто используют переданные пользователем данные повторно в других скрытых процессах. Если этот же пейлоад долетит до внутренних операторов UPDATE или DELETE, условие OR 1=1 заставит базу обновить или полностью уничтожить все данные в таблице.
