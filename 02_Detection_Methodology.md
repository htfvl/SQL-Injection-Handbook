## 🟢 04.7) MANUAL DETECTION / РУЧНОЕ ОБНАРУЖЕНИЕ SQLi

Обнаружение SQL-инъекций вручную строится на отправке систематического набора тестов против **каждой потенциальной точки входа** в приложении (параметры URL, тела POST-запросов, значения Cookie, заголовки HTTP). 

Для этого используют четыре основных метода анализа входных данных:

---

### 1️⃣ Синтаксический тест (Инициация ошибки)
Самый быстрый способ прощупать параметр — отправить спецсимвол, ломающий строковые литералы:
* **Пейлоад:** `'` (одинарная кавычка), `"` (двойная кавычка) или `/` (обратный слэш).
* **Что ищем:** Ошибки базы данных в HTTP-ответе (например, *Internal Server Error*, *SQL syntax error*), полную пропажу контента со страницы или любые другие аномалии в поведении приложения. Если поведение изменилось — бэкенд вставляет этот параметр в запрос «как есть».

---

### 2️⃣ Булев анализ (Логическое тестирование)
Метод заключается в отправке специфичного для SQL синтаксиса, который оценивает оригинальное значение точки входа в сравнении с заведомо истинным или ложным утверждением. Пентестер ищет систематические различия в ответах сервера.
* **Пейлоады для тестирования:**
  * Истинное условие (True): `category=Gifts'+OR+1=1--+` или `category=Gifts'+AND+1=1--+`
  * Ложное условие (False): `category=Gifts'+OR+1=2--+` или `category=Gifts'+AND+1=2--+`
* **Что ищем:** Различия в контенте. Если при `1=1` страница отображается нормально (или вываливает все товары), а при `1=2` возвращает пустой результат или ошибку «Товары не найдены» — параметр на 100% уязвим к **Boolean-based SQLi**.

---

### 3️⃣ Временной анализ (Time-Based тесты)
Используется, когда приложение скрывает любые ошибки СУБД, а контент страницы никак не меняется при логических манипуляциях (базовый слепой сценарий). Полезная нагрузка заставляет базу «зависнуть» на вычислениях.
* **Пейлоады для тестирования (зависят от СУБД):**
  * MySQL: `'+AND+SLEEP(5)--+`
  * PostgreSQL: `'+AND+pg_sleep(5)--+`
* **Что ищем:** Разницу во времени задержки ответа (`Time-to-First-Byte`). Если сервер стабильно возвращает ответ с задержкой в 5 секунд (или кратно больше, если запрос обрабатывает несколько строк), значит инъекция успешно выполнилась на стороне СУБД.

---

### 4️⃣ Внеполосный анализ (OAST / Out-of-Band тесты)
Самый мощный метод ручного тестирования скрытых инъекций, когда сервер вообще не возвращает никаких признаков уязвимости в HTTP-ответе и блокирует временные задержки. Пейлоад заставляет СУБД совершить сетевой запрос во внешний мир на подконтрольный хост.
